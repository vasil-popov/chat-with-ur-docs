## ГЛАВА 2. ТЕОРЕТИЧНИ ОСНОВИ И АНАЛИЗ НА СЪЩЕСТВУВАЩИ РЕШЕНИЯ

### 2.1 Анализ на проблемната област
- **Съдържание:** какво е „агентна система“ — LLM + инструменти + контролен поток;
  разлика спрямо обикновен чатбот; класове задачи (действие/запис, извличане, разговор).
- **Включва:** проза; евентуално таксономична схема _(Фиг. по избор)_.

### 2.2 AI агенти и парадигмата ReAct _(Фиг.: цикъл ReAct)_
- **Съдържание:** ReAct = редуване Reasoning → Action → Observation до краен отговор;
  как `create_react_agent` реализира този цикъл. Цитат към оригиналната статия
  (Yao et al., 2023).
- **Включва:** _(Фиг.)_ диаграма на ReAct цикъла; цитат.

### 2.3 Агенти с достъп до инструменти (tool-calling)
- **Съдържание:** function/tool calling, schema на инструмент, как моделът избира
  инструмент и извлича аргументи; връзка с двете измервани оси (избор + аргументи).
- **Включва:** проза; малък пример за схема на инструмент _(Фиг. по избор)_.

### 2.4 Multi-agent и supervisor архитектури _(Фиг.: супервайзор→специалисти)_
- **Съдържание:** идеята за рутер/супервайзор и специализирани под-агенти;
  предимства (фокус, по-малки промптове) и рискове (режийни извиквания, зацикляне).
  Цитати към LangGraph документация и съответни източници.
- **Включва:** _(Фиг.)_ обобщена схема; цитати.

### 2.5 Retrieval-Augmented Generation (RAG)
- **Съдържание:** chunking → embeddings → векторно търсене → синтез с цитиране на
  източник; защо е нужно за Q&A върху качени документи. Цитат (Lewis et al., 2020).
- **Включва:** _(Фиг. по избор)_ RAG конвейер; цитат.

### 2.6 Model Context Protocol (MCP)
- **Съдържание:** MCP като стандарт за изнасяне на инструменти от отделен процес;
  предимство — споделен слой с инструменти, използваем еднакво от двете архитектури.
- **Включва:** проза; цитат към MCP спецификацията.

### 2.7 Преглед на съществуващи решения и рамки _(Фиг.: схеми)_
- **Съдържание:** по примера — кратък обзор на 3–4 рамки/решения (LangChain/LangGraph,
  AutoGen, CrewAI, евентуално OpenAI Assistants), всяка като под-точка: какво предлага,

- **Включва:** по една _(Фиг.)_/диаграма на решение (както примерът дава екранни снимки
  на конкурентите); цитати.

### 2.8 Методи за оценка на агентни системи и избор на метрики
- **Съдържание:** подходи за оценка — базиран на правила скорер срещу LLM-съдия;
  предимства/слабости на всеки; защо тук правило-базираният е основен, а съдията —
  допълнителен. Въвеждане на понятията task_success, точност на инструмент/аргументи.
- **Включва:** проза; сравнителна таблица „метод → какво улавя → ограничения“ _(Табл. по избор)_.

### 2.9 Изводи след обзора и аргументация на избрания подход

### 5.2 Измервани оси и метрики
- **5.2.1 Коректност** — маршрутизация (само супервайзор), избор на инструмент (lenient
  subset), извличане на аргументи (по параметър, с толеранс).
- **5.2.2 Ефективност** — латентност (total + TTFT), токени (prompt/completion/total),

- **5.2.3 Безопасност и халюцинации** — незаявени записи при `no_write_expected`;

- **Включва:** _(Табл.)_ ос → метрика → дефиниция; кратко описание на `MetricsCallbackHandler`.

### 5.3 Базиран на правила скорер и `task_success` _(Табл.: проверки по категория)_
- **Съдържание:** чист модул без I/O; всяка проверка връща `True/False/None` (`None` =

### 5.5 Експериментална постановка и възпроизводимост
- **5.5.1 Изолирана среда** — отделен `EVAL_POSTGRE_*` engine; твърда защита: име на БД
